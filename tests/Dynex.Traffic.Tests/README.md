# Traffic ownership component

Run `dotnet run --project tests/Dynex.Traffic.Tests/Dynex.Traffic.Tests.csproj -c Release` on Windows. The runner links only `src/Dynex.Shaper/TrafficOwnership.cs` and needs no kernel backend, third-party library, admin rights, driver download, firewall change or installation.

`InboundPacketParser.TryParse(ipPacket, out SocketFlow)` and the overload with `out int transportPayloadLength` accept a raw inbound IPv4/IPv6 packet beginning at its IP header. Local means IP destination, remote means source. IPv4 options and IPv6 Hop-by-Hop/Routing/Destination/AH extension lengths are parsed within declared bounds. All fragments, IPv6 jumbograms, ESP, active routing headers, unsupported transports and malformed/truncated lengths return false. Checksums are not validated; the capture backend/OS validates received traffic. TCP payload excludes its variable header; pure ACK/SYN/FIN/RST packets have zero payload. Deciding which flows to limit belongs to the caller.

`TrafficOwnership.Refresh()` builds a separate immutable `OwnershipSnapshot` using all four Windows owner-PID tables. Call it on a worker, for example every 250 ms. `Snapshot.Classify(flow)` returns `TrafficOwner?`; null means missing, ambiguous, incomplete or older than one second. `Snapshot.IsFresh`, `Age`, `IsComplete`, `CapturedAtUtc`, `EntryCount` and `TrafficOwnership.LastError` expose state. Any failed table query immediately publishes an empty incomplete snapshot. No old successful table is kept as a silent fallback. `Dispose` clears the published view; any previously saved view still expires by monotonic age. No native buffer or process handle survives a refresh.

`TrafficOwner` supplies PID, nullable process creation timestamp and optional normalized lower-case process name. Native refresh queries each process once per snapshot, at most 4096 identities, and never queries processes from the packet-classification path. Inaccessible/exited process identities are classified unknown. Compare both PID and creation timestamp to protected game identities; PID alone can be reused. A process created after capture start cannot validate an earlier row. Snapshots are inherently a short-lived observation: socket closure/port reuse and process termination can happen between table capture and packet arrival, so classification does not provide a kernel-atomic ownership guarantee.

TCP requires an exact local+remote tuple; listening wildcards do not catch unrelated traffic. UDP tables expose only local binds and cannot prove remote per-packet ownership. Exact and wildcard candidates must all identify the same owner, otherwise classification is unknown. A single unambiguous wildcard bind can be assigned to its unique owner. The tables do not expose `IPV6_V6ONLY`; any same-port IPv6 wildcard makes IPv4 UDP classification conservatively unknown. Scoped IPv6 keys ignore zone IDs absent from raw packet headers; conflicting same-address scoped owners become unknown. Shared/reused UDP ports and system/broker-owned sockets can remain unknown, so callers must let them pass. This component does not select games/communication apps, detect bulk transfers, impose a rate, or change an existing filter.

The deterministic tests cover bounds, extension chains, fragments, malformed packet fuzzing, port byte order, ambiguity, wildcards, PID creation mismatch, scoped/mapped IPv6, immutable keys and stale views. Live tests create IPv4 and IPv6 loopback TCP connections plus UDP sockets, then verify the actual current PID/start timestamp/name through read-only OS tables. They do not claim Internet traffic shaping or physical multi-PC validation.

Native ABI and byte order follow Microsoft primary documentation: [GetExtendedTcpTable](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getextendedtcptable), [GetExtendedUdpTable](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getextendedudptable), [IPv6 TCP owner row](https://learn.microsoft.com/en-us/windows/win32/api/tcpmib/ns-tcpmib-mib_tcp6row_owner_pid), [IPv6 UDP owner row](https://learn.microsoft.com/en-us/windows/win32/api/udpmib/ns-udpmib-mib_udp6row_owner_pid). Table allocations and counts are bounded; `ERROR_INSUFFICIENT_BUFFER` only retries a reported size race, at most three times.
